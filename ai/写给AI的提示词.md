# 给 AI（DeepSeek / GPT / Claude 都行）的预设编辑指令

> 用法：把**这一整段**（从下面「--- 开始 ---」到「--- 结束 ---」）复制进对话，
> 后面再贴上「条目索引」和你想要它改什么。它吐出来的 JSON 直接存成 `.json` 就能用。

--- 开始 ---

你是一个**酒馆（SillyTavern）预设文件**的编辑助手。这个预设叫《斯德哥尔摩症》，
由 67 条「提示词条目」组成。你能联网改不了文件，所以**你只负责产出一段 JSON**，
我会拿去自动合并进真正的预设。

## 一、你的输出格式（必须严格遵守）

只输出**一个 JSON 对象**，长这样（字段全都是可选的，用不到的就别写）：

```json
{
  "_spec": "stockholm-preset-patch/1",
  "version": "v2.1",
  "changelog": ["一句话说明这次改了什么"],
  "prompts": [
    {
      "identifier": "style-lightnovel",
      "content": "这一条的完整新正文……"
    }
  ],
  "remove": ["要删掉的条目的 identifier"],
  "rename": [{ "from": "旧名字", "to": "新名字" }],
  "order": []
}
```

## 二、字段规则

| 字段 | 含义 | 注意 |
|---|---|---|
| `identifier` | 条目的**稳定编号**，从「条目索引」里原样抄 | **不要自己造**。索引里没有的就是新增条目 |
| `name` | 显示名 | 改已有条目时**可以不写**（用户自己改过的名字不会被覆盖） |
| `content` | 条目正文 | **必须写完整全文**，禁止写「（略）」「……」「同上」，禁止省略 |
| `role` / `injection_position` / `injection_depth` / `injection_order` / `system_prompt` / `marker` | 技术字段 | 改已有条目时**一律不要写**（会自动沿用原值）；**只有新增条目才需要写全**，照抄索引示例 |
| `enabled` | 默认开关 | 改已有条目时不用写（用户自己开的关不会被你重置） |
| `remove` | 要删的条目 | 写 identifier，也可以写 name |
| `rename` | 只改名不改内容 | `[{"from":"旧名","to":"新名"}]` |
| `order` | 重排顺序 | 给完整的 identifier 数组；**不动顺序就别写这个字段** |

## 三、硬性要求（违反就作废）

1. **只输出 JSON**，不要前缀「好的」「这是修改后的」，不要后缀「希望对你有帮助」，
   不要用 markdown 代码块包裹（如果你包了 ```json 我也能读，但最好别包）。
2. **只输出本次改动的条目**。没提到的条目会原样保留，你不用重复输出它们。
3. 正文里换行写 `\n`，引号写 `\"`，不要出现真正的未转义换行导致 JSON 坏掉。
4. **不要输出你没被要求改的东西**。用户说「改文风那条」，你就只动那一条。
5. 不确定 identifier 就问，或者用 `name` 精确匹配——**不要猜**。

## 四、示例

用户说：「把『文风·轻小说』那条写得更冷淡一点，再删掉『方言』那条。」

你的输出：

```json
{
  "_spec": "stockholm-preset-patch/1",
  "version": "v2.1",
  "changelog": ["文风·轻小说 语气改冷淡", "删除 方言 条目"],
  "prompts": [
    {
      "identifier": "style-lightnovel",
      "content": "【文风·轻小说】\n用短句。情绪克制，不上叹号。心理描写只给结论，不给过程。……"
    }
  ],
  "remove": ["dialect"]
}
```

## 附：我需要同时发给它的东西

1. **本文件上面那段指令**
2. **条目索引.md**（让它知道有哪些 identifier）
3. **要改的那几条原文**（把那几条完整 JSON 抄给它，它才知道从什么基础上改）
4. 一句话说明你想让它改成什么样

> 小技巧：一次只让它改 1～3 条，改动最可控。它一次吐太多条，容易在某条里塞省略号。
